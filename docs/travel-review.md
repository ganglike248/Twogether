## 묶음 1 — 데이터·표시가 틀어지는 것 (먼저)
- ☑ **B1 여행 상태 자동 계산**: 날짜로 '다가오는 / 진행 중 / 다녀옴' 계산(순수 함수 + 테스트), 수정 모달의 '여행 상태' 칸 제거,
  목록 필터를 계산값 기준으로. 저장된 `status`는 건드리지 않고 안 읽음. (`TripModal.js`, `TravelPlanPage.js`, `TripCard.js`, `TripDetailHeader.jsx`)
- ☑ **B2 기간을 줄일 때 잘리는 일정**: 저장 전에 "Day N~M 일정 K개가 있어요" 확인 → 마지막 날로 옮기기 / 그대로 지우기 / 취소.
  보고 있던 Day가 없어지면 마지막 Day로. 예산 합계는 기간 안의 Day만. (`TripDetail.js`, `tripService.js`)
- ☑ **B6 체크리스트 빈 목록 덮어쓰기**: 탭을 열 때 미리 만들지 않고, 첫 항목을 추가할 때만 생성(없으면 만들고 있으면 트랜잭션).
  기기 저장본에서 온 '없음'으로는 쓰지 않음. (`TravelChecklistTab.jsx`, `travelChecklistService.js`)

## 묶음 2 — 여행 중에 자주 쓰는 동작
- ☑ **B3 '첫 일정 추가하기'가 이전 일정을 엶**: 모달이 닫힐 때(주소 기준) 선택한 일정 비우기, 추가 버튼은 항상 빈 폼으로.
- ☑ **B4 안드로이드 뒤로가기로 모달 닫기**: 후보 추가/수정 시트·비교 주제 모달·체크리스트 모달·날짜 고르기·사진 추가를
  `?modal=`에서 파생(앱 모달 규칙). 확인창은 그대로.
- ☑ **B5 완료 체크**: 누르면 바로 반영(실패하면 되돌리고 안내). 오프라인이면 "연결되면 다시 시도해 주세요" 안내.
- ☑ **B7 틀린 제목**: 후보에서 온 새 일정 "새 일정 추가"(id 유무로 판단). (지도에서 온 새 여행 제목은 묶음 1에서 같이 고침)
- ☑ **B8 탭 위치를 주소에**: `?tab=decisions|checklist`(replace), 새로고침·딥링크에도 같은 탭.

## 묶음 3 — 문구·일관성·접근성 (양 적음)
- ☐ 용어 통일: **비교 주제**(카테고리·선택지 X) / **후보**(옵션 X) — 버튼·알림·확인창 전부.
- ☐ '~어요'체 5곳: "정말 삭제하시겠습니까?"(일정), "이 옵션을/선택지를 삭제하시겠습니까?", "이 항목을 삭제하시겠습니까?", "아직 선택지가 없습니다".
- ☐ 비교 주제 삭제 확인에 "후보 N개도 함께 삭제돼요".
- ☐ 여행 추가 모달: 바깥 눌러도 안 닫히게(일정 모달과 같게).
- ☐ 예산·비용 칸 숫자 키패드(`inputMode="numeric"`).
- ☐ 접근성: 후보 상세·후보 추가·사진 추가·보기 설정 시트·날짜 고르기 창에 `useDialog`, × 버튼 이름(aria-label).
- ☐ 색 직접 적은 2곳 → 변수(`TripCard.js:74`, `ScheduleTimeline.jsx:69`).

## 묶음 4 — 사용성 다듬기
- ☐ 여행 목록: '진행 중 / 다가오는 / 지난' 구역 + D-day(B1 계산 재사용). **시안 먼저.**
- ☐ 목록 카드의 일정표 구독 제거(예산 합계는 상세에서만, 또는 여행 문서에 합계 저장).
- ☐ 당일치기는 "어느 날에 추가할까요?" 건너뛰기.
- ☐ 카드에서도 평가 전 확정 가능(상세 시트와 같게) — 버튼 구성은 시안에서.
- ☐ 이동 수단 고르기(자동차·도보·대중교통 아이콘).
- ☐ 시간 없는 일정 순서 바꾸기(위·아래 버튼).
- ☐ 일정 삭제 시 이동 시간 데이터도 삭제.
- ☐ 체크리스트: 마감 지난 항목 강조, 완료 항목도 수정 가능.
