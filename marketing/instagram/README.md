# 우리두리 인스타그램 게시물 — 이어서 작업하는 사람을 위한 안내

이 문서만 읽으면 지금까지 만든 것, 만드는 방법, 지켜야 할 방향, 남은 일을 알 수 있어요.
(마지막 정리: 2026-11-27, 앱 버전 v1.2.7)

## 1. 한눈에 보기

- **목적**: 인스타그램에서 우리두리를 처음 보는 커플이 "나도 필요하겠다"고 느끼고 설치하게 하는 것
- **형식**: 게시물 하나 = 여러 장(캐러셀), 한 장은 **1080×1350(4:5)** PNG
- **스토어**: 지금은 **Google Play만** 공개. App Store는 문구에 넣지 않아요
- **완성된 게시물 7개** — 올릴 이미지는 각 폴더의 `out/01.png …`

| 번호 | 주제 | 장 수 | 표지 배경 | 표지 구성 |
|---|---|---|---|---|
| post-01 | 앱 소개 | 8 | 분홍 | 두 주인공의 대화 말풍선 |
| post-02 | 공유 캘린더 | 7 | 하늘색 | 기울어진 달력 |
| post-03 | 여행 계획 | 7 | 연보라 | 숙소 후보 + 일정표 두 장 겹침 |
| post-04 | 하고 싶은 것 · 돌림판 | 7 | 연노랑 | 화면 밖으로 넘치는 큰 돌림판 |
| post-05 | 봉인 편지 · 우리 이야기 | 7 | 민트 | 기울어진 편지 두 통 |
| post-06 | 우리 지도 · 추억 | 7 | 살구색 | 화면 밖으로 넘치는 큰 지도 |
| post-07 | 처음 시작하는 방법 | 7 | 연두색 | 연결 방법 선택 카드 |

게시물마다 구성은 같아요: **표지 → 기능 장 4~6장 → 마무리 장**(마스코트 + "Google Play에서 '우리두리' 검색").

## 2. 파일 구조

```
marketing/instagram/
  base.css            슬라이드 틀(제목·표지·마무리 장) 스타일
  app.css             앱 화면을 본뜬 그래픽 스타일(주아 + 고운돋움, 크림색 카드)
  post-01/intro.html  1번 게시물의 표지·소개 장(손으로 만든 장, 직접 고침)
  post-XX/slides.html build.py가 만드는 파일 — 직접 고치지 않아요
  post-XX/out/*.png   올릴 이미지(커밋함)
  shots/              실제 앱 화면 캡처(참고용, 커밋 안 함 — 다시 만들 수 있음)

scripts/instagram/
  build.py    게시물 구성(어떤 장에 어떤 제목·그래픽) → slides.html 생성
  ui.py       그래픽 조각(달력, 일정 모달, 일정표, 돌림판, 편지함, 지도 …)
  render.mjs  slides.html → out/*.png (Playwright)
  sheet.py    한 게시물을 한 장에 모아 보기(확인용)
  capture.mjs / capture.sh   실제 앱 화면을 찍어 shots/에 저장(참고용)
```

## 3. 만드는 방법

```bash
python scripts/instagram/build.py            # 모든 게시물의 slides.html 다시 생성
node scripts/instagram/render.mjs post-05    # 그 게시물의 out/*.png 다시 뽑기
python scripts/instagram/sheet.py post-05    # post-05/sheet.png 로 모아 보기(확인 후 지워도 됨)
```

- **문구·장 순서를 바꿀 때**: `build.py`에서 해당 `write('post-XX', …)` 블록의 `slide(tag, 제목 첫 줄, 제목 둘째 줄(분홍), 설명, 그래픽)`을 고쳐요.
- **그래픽 내용을 바꿀 때**: `ui.py`의 해당 함수(예: `calendar()`, `wheel_modal()`)를 고쳐요. 여러 게시물이 같은 함수를 쓰니 영향 범위를 확인하세요(예: `day_modal()`은 1번·2번에 같이 나와요).
- **1번 표지·소개 장을 바꿀 때**: `post-01/intro.html`을 직접 고쳐요.
- **지도**: `<!--MAP:11,26,47-->`(칠할 시·도 코드), `<!--SGG:51:51150-->`(시·도:칠할 시·군·구)를 넣으면 `render.mjs`가 앱의 실제 경계(`src/components/Map/data`)로 바꿔 줘요.
- 그래픽이 남는 높이보다 크면 자동으로 줄여서 맞춰요. **글씨가 작아 보이면 그래픽 안의 항목을 덜어 내세요**(자동 축소가 원인).
- 필요한 것: Python(Pillow), Node, Playwright(`npx playwright install chromium`을 한 번 실행). 글꼴은 렌더할 때 인터넷에서 불러와요(Jua, Gowun Dodum, Pretendard).

### 새 게시물을 만드는 순서

1. **실제 화면부터 찍기** — `capture.mjs`의 `SHOTS`에 찍을 화면을 추가하고 실행:
   ```bash
   SHOTS=이름1,이름2 bash scripts/instagram/capture.sh    # 일부만
   bash scripts/instagram/capture.sh                       # 전부(1~2분)
   ```
   Firebase 에뮬레이터(데모 프로젝트, 운영 데이터와 무관)에 게시물용 데이터를 넣고 앱을 띄워 `shots/`에 저장해요. Java가 필요해요.
2. 찍힌 화면을 보고 **같은 모양으로 `ui.py`에 그래픽 함수를 추가**(스타일은 `app.css`).
3. `build.py` 맨 아래에 `write('post-08', …)` 블록 추가 — 표지 배경색은 앞 게시물과 겹치지 않게.
4. build → render → sheet로 확인.

## 4. 지켜야 할 방향 (사용자가 직접 정한 것)

작업 중 받은 피드백이에요. 새 게시물도 이 기준을 따라야 해요.

**표지**
- 표지는 관심을 끌어야 하고, **게시물마다 달라 보여야** 해요. 같은 구성이 반복되면 안 돼요.
- **귀엽고 궁금하게**. 1번 표지는 마스코트 두 명의 대화 + "이 대화, 어제도 한 것 같다면"으로 확정(여러 시안 중 고른 것).
- 대화는 **날카롭거나 타박하는 말투 금지**. 둘 다 깜빡하는, 공감 가는 편한 대화로.

**색·톤**
- **어두운 색 금지**. 진한 장밋빛(#E07A93) 바탕의 카드·말풍선은 두 번 거절당했어요. 강조도 연한 분홍 바탕 + 어두운 글씨로.
- 반짝이·그라데이션·이모지 없이 깔끔하게("AI 티 안 나게").
- 글자를 크게 키우는 것보다 **한눈에 핵심이 보이는 것**이 우선.

**화면 그래픽**
- **실제 화면 캡처를 그대로 붙이지 않아요.** 캡처는 참고만 하고, 같은 글꼴·색·모양으로 **다시 그린 그래픽**을 써요.
- 그래도 **실제 화면과 최대한 비슷하게**. 문구·숫자·버튼 이름은 캡처한 화면 그대로 쓰고, 없는 기능은 그리지 않아요.

**내용**
- **공유 캘린더가 중심 메시지**예요. "서로 일정을 매일 헷갈려서 '내일 어디 간다 했지?'를 계속 묻는다 → 한 캘린더에서 같이 계획하고 기록한다."
- 1번 게시물에서 장점을 다 보여 주고, 이후 게시물에서 기능별로 자세히.
- 두 주인공 이름은 **하나**(파란 친구, 화면을 보는 사람)와 **두리**(살구 친구).
- 문구는 앱과 같은 **'~어요'체**.

**일하는 방식**
- 마음에 안 든다고만 할 때는 짐작으로 고치지 말고 **시안 2~3개를 뽑아 고르게** 해요(표지, 마무리 멘트에서 이렇게 했어요).
- 게시물 하나를 끝내면 확인받고, **"커밋하고 다음"이라고 할 때만 커밋**해요.

## 5. 사실 확인 메모 (틀리기 쉬운 것)

코드와 실제 화면으로 확인한 내용이에요. 문구를 쓸 때 어기지 마세요.

- 일정에는 **시간 입력이 없어요**(날짜만). 시간은 메모에 적는 모습으로 그려요. 여행 일정표에는 시간이 있어요.
- 알림 시점: 상대가 일정 추가 → 바로 / 내일 일정 → 전날 저녁 9시 / **디데이**로 표시한 일정·여행 → 3일 전·하루 전 아침 9시 / **기념일(100일 단위·매년)은 당일** 아침 9시.
- 일정 종류 버튼은 **데이트 / (하나) / (두리)** — 닉네임이 그대로 나와요.
- 예산은 일정표에 적은 비용의 합이에요.
- 하고 싶은 것: '해보고 싶은 것'(하면 '이룬 것'으로) / '자주 할 것'(횟수·기록이 쌓임).
- 봉인 편지 예약 시각은 15분 단위예요.
- 게시물 속 이야기: 오늘은 11월 27일, 강릉 1박 2일은 12월 18~19일(예산 40만 원 중 21만 원), 함께 가 본 곳 4/16(서울·부산·경북·제주). **6번 게시물만** 강릉을 다녀온 뒤라 5/16이에요.
- "무료 설치"라고 썼어요(코드에 결제·광고 없음). 스토어 표기와 다르면 고쳐야 해요.

**캡처하지 못해 그리지 않은 화면**: 휴대폰 알림 자체, 링크로 자동 채우기, 수정 기록, 초대 코드가 만들어진 직후 화면, 연결 완료 화면, 연말 랩업, 여행 끝 기록 3단계.

**실제와 다를 수 있어 확인이 필요한 곳**
- 3번 "여행 끝 기록"의 TOP 3 번호 동그라미(고른 상태 모양을 못 봄)
- 5번 "다음 달 미리 보기"의 D-3·D-11 표기(실제 캡처는 지난달이라 "D-day"로 찍힘)
- 1번·2번의 "나만 보기" 관련 내용은 뺐어요(일정 추가 화면에서 그 스위치를 못 봄)

## 6. 남은 일

**더 만들 수 있는 게시물** (추천 순)
1. **알림 모아 보기** — 일정 추가, 내일 일정, 디데이, 기념일, 여행 D-day, 편지 도착·공개, 월간 요약 알림과 종류별 켜고 끄기. 휴대폰 알림은 앱 화면이 아니라서 알림 설정 화면(`/notification-settings`)을 참고로 찍어야 해요(테스트 브라우저에는 알림 권한이 없어 종류 목록이 안 보일 수 있음).
2. **연말 랩업** — 12월 31일~1월 7일에 뜨는 한 해 요약(`/recap/2026`). 커플 일정이 5개 이상 있어야 해요. 연말에 맞춰 올리기 좋아요.
3. **홈 화면 한 바퀴** — '오늘' 탭과 '우리 이야기' 탭, 함께한 날 수, 홈 사진.
4. **색·카테고리 꾸미기** — 일정 색 바꾸기, 하고 싶은 것 카테고리.
5. **안심 정보** — 둘만 보는 공간, 데이터 백업, 연결 해제 시 30일 보관, 오프라인 저장.
6. **여행 심화** — 링크로 자동 채우기, 여행 끝 기록 전체 흐름.

**게시물 말고 남은 것**
- **캡션·해시태그**: 게시물마다 올릴 글은 아직 없어요.
- **1~6번 마무리 장 멘트**: 7번만 사용자가 고른 문구("둘이 쓰는 첫 캘린더, 오늘 시작해 볼까요?" + "이 글을 같이 쓸 사람에게 보내 주세요")로 바꿨어요. 1~6번은 처음 쓴 멘트("내일 일정부터 같이 적어 볼까요?" 등 + "다음 글 …")가 그대로인데, 7번의 예전 멘트를 마음에 안 들어 했으니 같이 바꿀지 물어보세요.
- **글씨가 작은 장**: 내용이 많은 그래픽은 작게 나왔어요 — 2번 반복 일정, 3번 일정표·준비물, 4번 돌림판, 5번 월간 요약 두 장, 6번 지도 두 장.
- **앱 쪽 확인(게시물과 별개)**: 하고 싶은 것 화면(`/bucket`)의 "어제 하기로 한 것 … 했어요?" 카드가 홈과 달리 테두리·여백 없이 깨져 보였어요(`shots/bucket.png`).

## 7. 걸려 넘어졌던 곳

- **스타일 이름 충돌**: `base.css`와 `app.css`가 한 페이지에 같이 실려요. 짧은 이름(`.q`, `.ago` 등)이 겹쳐 그래픽이 깨진 적이 두 번 있어요. 새 클래스는 겹치지 않는 이름으로.
- **`.ui.sheet`처럼 붙여 써야 하는 선택자**: 그래픽 뿌리 요소에 직접 붙는 클래스는 `.ui .sheet`(띄어 씀)로 쓰면 안 먹어요.
- **캡처가 "포트가 이미 사용 중"으로 실패**하면 이전 실행이 남긴 개발 서버가 5198 포트를 잡고 있는 거예요. 그 프로세스를 끝내고 다시 실행하세요.
- **개발 서버가 패키지를 못 찾으면** `npm install`을 한 번 실행하세요.
- 이 프로젝트의 커밋 규칙: 커밋마다 `package.json`·`version.txt` 버전을 같이 올리고, 메시지는 `v{버전} - {설명}`, 항상 `git add .`. 자세한 규칙은 루트 `CLAUDE.md`.

## 8. 릴스 소개 영상

- 결과물: `marketing/instagram/reel/reel.mp4` (1080×1920, 30fps, 26초, 소리 없음 — 음악은 인스타그램에서 넣어요)
- **게시물과 별개의 구성**이에요. 처음에 게시물 그래픽을 그대로 움직인 버전을 만들었다가 "게시물과 똑같아서 별로"라는 피드백으로 버렸어요. 릴스에는 게시물 그래픽(`ui.py`)을 쓰지 않아요.
- 지금 구성: 마스코트 둘(하나·두리)을 SVG 캐릭터로 직접 그려 움직이는 짧은 이야기
  1. 화면이 둘로 나뉘고 각자 "내일… 뭐였더라?" 하며 헷갈림
  2. 말풍선이 오가며 "오늘만 3번째 질문"
  3. 화면이 하나로 합쳐지고, 둘이 달력 아래로 모이면 일정이 달력으로 날아가 앉음 → "안 물어봐도 다 보여요"
  4. 여행 가방 · 돌림판 · 편지(큰 글자 한 줄씩)
  5. 하트 풍선을 든 둘 + 우리두리 + Google Play 안내
- 만드는 방법: `python scripts/instagram/reel.py`(화면 HTML 생성) → `node scripts/instagram/reel.mjs`(한 프레임씩 찍어 MP4로 묶음, 3분쯤). 몇 장만 미리 보려면 `node scripts/instagram/reel.mjs --stills 3200,10500`(밀리초).
- 필요한 것: Playwright, `pip install imageio-ffmpeg`(MP4로 묶는 ffmpeg가 들어 있어요)
- 장면 시각은 `reel.py`의 `BODY`에 밀리초로 적혀 있어요. 캐릭터가 뛰는 시각은 `HOPS_H`/`HOPS_D`.
- 움직임은 부드럽게 멈추는 곡선(`SOFT`), 살짝 튕기는 곡선(`SPRING`), 천천히 출발해 천천히 멈추는 곡선(`INOUT`)만 써요. 딱딱한 직선 움직임은 쓰지 않아요.
- 화면 위 250px, 아래 350px쯤은 릴스 화면의 글자·버튼에 가려지니 중요한 내용을 두지 않아요.
