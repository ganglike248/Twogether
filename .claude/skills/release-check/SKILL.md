# release-check

"마무리"·"배포" 직전에 실행. 결과는 짧게 보고(문제·확인 필요 항목만).

## 1. 자동 점검
저장소 루트에서:
```bash
node .claude/skills/release-check/check.mjs
```
- ❌ 문제(버전 불일치)가 있으면 고친 뒤 진행. "마무리"라면 버전 올리기 단계에서 함께 맞춰도 됨
- ⚠ 항목은 각 줄을 실제로 열어보고 의도된 것인지 판단(예: 성공 초록, 장식용 그라데이션은 허용)
- **CSS 변수 삭제/이동 경고가 나오면 반드시 확인**: 그 변수를 쓰는 곳(`grep -rn "var(--이름" src`)과 새 기본값 위치

## 2. 빌드 한 번
```bash
npm run build
```

## 3. 배포 순서 (check.mjs가 안내한 대상만)
Functions → Firestore/Storage 규칙 → Hosting. 데이터 백업 복원 알림 스킵처럼 서버 쪽이 먼저 있어야 하는 변경이 있으므로 순서 바꾸지 말 것.

## 4. 수동 체크리스트 (사용자 안내용, 해당될 때만 언급)
- 앱 반영: 웹 변경도 앱엔 다음 AAB/Archive부터. AAB(Play)·Archive(App Store) 빌드·업로드는 사용자 수동
- R8 릴리즈 빌드는 내부 테스트 트랙에서 구글 로그인·푸시·인앱 업데이트·뒤로가기 확인
- 새 권한·데이터 수집이 생겼으면 Play 데이터 보안 / 개인정보처리방침 / iOS 개인정보 매니페스트 갱신
- 건강 관련 기능(생리주기 등)을 되살리면 Play 건강 앱 선언 필요(예전 반려 이력)
- 계정 삭제는 앱 안에서 가능해야 함(커플 없는 사용자 경로 포함)
- 인증 메일(비밀번호 재설정 등) 템플릿은 Firebase 콘솔에서 켜져 있어야 함
