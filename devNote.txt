<안드로이드 실행>

[앱 업데이트]
1. 코드 수정 후 버전 올리기

android/app/build.gradle 에서 버전 변경:
  versionCode 4        // 1씩 올려야 함 (무조건 이전보다 커야 함)
  versionName "0.4.24" // 사용자에게 표시되는 버전, package.json 버전과 맞추면 편함

2. 웹 빌드 + AAB 다시 빌드

npm run build
npx cap sync android
cd android
./gradlew bundleRelease

※ 반드시 위 순서(npm run build → cap sync → bundleRelease)를 지킬 것
  이유: 이 프로젝트는 Capacitor라서 gradlew가 웹(JS) 코드를 자동으로 새로
  빌드해주지 않음. npm run build를 안 하고 넘어가면 이전 dist/ 내용 그대로,
  npx cap sync를 빼먹으면 android/app/src/main/assets/public 이 갱신 안 돼서
  옛날 화면 그대로 배포됨. .env 값을 수정했을 때도 동일 — 반드시 npm run
  build부터 다시 실행해야 새 값이 번들에 반영됨.

3. 플레이 콘솔에 업로드

android/app/build/outputs/bundle/release/app-release.aab

내부 테스트 또는 비공개 테스트 → 새 버전 만들기 → 업로드

+ 실기기에 스토어(정식/테스트) 버전이 깔려있으면, 로컬에서 debug 키로 만든
  빌드는 서명이 달라서 설치 시 에러남 (기존 앱 먼저 삭제하고 설치할 것)


[개발 빌드] PC 없이 그냥 웹처럼 빠르게 확인
  npm run dev
  → http://localhost:5173 브라우저에서 확인 (네이티브 플러그인 없는 화면 위주 작업 시 충분)

  실기기/에뮬레이터에서 라이브 리로드로 보고 싶을 때:
  1. capacitor.config.ts 에서 server.url 주석 해제 후 PC IP:5173 입력
  2. npm run dev (켜둔 채로 유지)
  3. npx cap run android (USB 연결 실기기 또는 에뮬레이터 선택)
  → 코드 수정하면 앱에도 자동 반영됨
  ⚠ 배포 빌드 전에 capacitor.config.ts의 server 설정 반드시 다시 주석 처리할 것


[릴리즈 빌드] PC 연결 없이 완전 독립 실행되는 버전 확인
  npm run build
  npx cap sync android
  → Android Studio에서 Run 버튼으로 기기에 직접 설치
  (또는 cd android && ./gradlew installRelease, 서명 설정 필요)


[캐시 지운 후 시작]
  rm -rf node_modules/.vite
  npm run dev


[요소 확인 툴 켜기]
  Capacitor 앱은 WebView 기반이라 Metro 방식 react-devtools 연결은 안 됨
  1. 실기기 USB 디버깅 켜기
  2. 크롬 주소창에 chrome://inspect 입력
  3. 연결된 기기의 WebView 선택 → inspect
  → 크롬 개발자도구 Elements/Console 그대로 사용 가능

  순수 웹 버전(npm run dev)만 볼 때는 브라우저의 React Developer Tools
  확장 프로그램 쓰면 됨


[캐시 충돌 시 해결법 - Gradle 데몬]
1. Gradle 데몬 중지
  cd android
  ./gradlew --stop
2. node_modules 완전 재설치
  npm install
3. 웹 재빌드 + 동기화
  npm run build
  npx cap sync android
4. Android Studio에서 Build → Clean Project → Rebuild Project


[인앱 업데이트 (Google Play In-App Update)]
플러그인: @capawesome/capacitor-app-update (Android 전용, iOS는 API 자체 없음)
훅 위치: src/hooks/useInAppUpdate.js
연결 위치: src/App.jsx → <InAppUpdatePrompt /> (RootLayout에서 항상 마운트)

업데이트 방식 변경은 useInAppUpdate.js 상단의 UPDATE_TYPE 값만 바꾸면 됨:

  const UPDATE_TYPE = 'FLEXIBLE';   // 현재 설정
  const UPDATE_TYPE = 'IMMEDIATE';

  FLEXIBLE (유연) — 현재 설정
    다운로드가 백그라운드에서 진행되고 앱을 계속 쓸 수 있음
    다운로드 완료되면 toast로 재시작 안내 (누르면 재시작)
    일반적인 기능 업데이트에 적합

  IMMEDIATE (즉시)
    전체 화면을 덮는 업데이트 UI가 뜨고 완료 전까지 앱 사용 불가
    Google Play가 UI/재시작을 전부 알아서 처리
    보안 패치, 서버 호환성 필수 업데이트에 적합

※ Play Core In-App Update API는 Play Store를 통해 설치된 앱에서만 동작함.
  로컬 debug 빌드나 사이드로드 설치에서는 getAppUpdateInfo()가 업데이트
  없음으로 나오거나 동작하지 않음 — 반드시 내부/비공개 테스트 트랙에 올려서
  스토어로 설치한 뒤 테스트할 것.

※ 버전 올려서 새 AAB를 스토어에 올려야만 "업데이트 가능" 상태가 뜸.
  즉, 위 [앱 업데이트] 절차(versionCode/versionName 올리고 재빌드+업로드)를
  먼저 해야 인앱 업데이트 동작을 확인할 수 있음.


[푸시 알림 — 웹(PWA) + 네이티브(Android/iOS) 공존]
구조: notificationService.js 안에서 Capacitor.isNativePlatform()으로 분기.
  웹: 기존 firebase/messaging 웹 SDK + VAPID 그대로 (안 건드림)
  네이티브: @capacitor-firebase/messaging 플러그인 (Android/iOS 동일 API,
    둘 다 FCM 토큰을 직접 줘서 서버 코드 공유 가능)

호출부(NotificationSettingsPage.jsx, Home.jsx, NotificationPrimingModal.jsx,
Layout.jsx)는 전혀 안 바뀜 — enableNotifications() 등 기존 함수 인터페이스가
내부에서만 플랫폼별로 다르게 동작함.

서버(functions/index.js):
  - users 문서에 토큰을 두 필드로 분리: fcmTokens(웹, data-only 발송) /
    nativeFcmTokens(네이티브, notification 필드 포함 발송)
  - 이유: 네이티브 앱은 완전 종료 상태에서 JS가 안 돌아서 data-only로는
    알림이 안 뜸. notification 필드가 있어야 OS가 백그라운드/종료 상태에서
    알아서 표시해줌. (포그라운드는 클라이언트가 토스트로 직접 표시)
  - registerFcmToken 콜러블에 platform 인자 추가 ('web'(기본값) | 'android' | 'ios')

★★★ 아래 항목들은 코드가 아니라 콘솔/계정 설정이라 직접 해야 동작함 ★★★

1. Android: google-services.json 없음 (현재 프로젝트에 파일 자체가 없음)
   Firebase 콘솔 → 프로젝트 설정 → Android 앱 추가(패키지명
   com.wooridoori.twogether, 이미 등록돼 있으면 재사용) → google-services.json
   다운로드 → android/app/google-services.json 에 저장
   (build.gradle에 이미 조건부 적용 코드 있음 — 파일만 넣으면 자동 인식됨)

2. iOS: GoogleService-Info.plist 없음
   Firebase 콘솔 → iOS 앱 추가(번들 ID com.wooridoori.twogether) →
   GoogleService-Info.plist 다운로드 → ios/App/App/GoogleService-Info.plist 에 저장
   → Xcode에서 이 파일을 App 타겟에 포함시켜야 함(파일 추가 시 타겟 체크박스 확인)

3. iOS: APNs 인증키 업로드 (Apple Developer 계정 필요, $99/년)
   Apple Developer 사이트 → Certificates, Identifiers & Profiles → Keys →
   APNs 인증키(.p8) 생성 → Firebase 콘솔 → 프로젝트 설정 → Cloud Messaging →
   Apple 앱 구성에 업로드
   (이거 없으면 토큰은 받아도 실제 푸시가 안 감)

4. iOS: Xcode capability 설정
   Xcode에서 App 타겟 → Signing & Capabilities → + Capability →
   "Push Notifications" 추가 (entitlements 파일 자동 생성됨)
   Background Modes capability도 추가 → "Remote notifications" 체크
   (Info.plist에는 이미 UIBackgroundModes 추가해둠, Xcode capability는 별도로 켜야 함)

1번(Android) 없이는 네이티브 알림 테스트 자체가 안 되고, 2~4번(iOS)은 Mac +
Apple Developer 계정 있어야 진행 가능. 순서상 Android 먼저 끝내고 테스트한
뒤 iOS로 넘어가는 걸 추천.
